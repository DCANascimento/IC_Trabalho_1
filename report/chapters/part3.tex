\section{Our Implementation}

Similarly to the previous codec, this one was split into:

\begin{itemize}
    \item \textbf{codec.cpp} orchestrates the entire compression and decompression pipeline. It handles WAV reading, coordinates the MDCT/DCT transforms, manages quantization, executes rate control via binary search, and packs/unpacks the file headers containing the `LSY6` magic tag, block size, step, and reconstruction offsets.
    
    \item \textbf{transform.cpp} implements the mathematical core of the codec. It applies the sine window, handles block overlapping, and computes the MDCT/DCT efficiently by folding the input into a DCT-IV using an internal FFT.
    
    \item \textbf{zigzag.cpp}, like in the previous codec, maps signed quantized integers into unsigned integers. This transformation groups small numbers together, preparing them for more efficient entropy coding later on.
    
    \item \textbf{rice.cpp} handles Rice coding and features an adaptive context predictor. Later on, instead of storing a global k value, it wpuld look at 8 neighboring coefficients (from the current and previous blocks) to dynamically predict the optimal Rice parameter k on the fly for every single coefficient with zero metadata overhead. But at the first implementation, this value was static.
    
    \item \textbf{bitstream.cpp} provides low-level bit manipulation via `BitWriter` and `BitReader`. It packs variable-length Rice codes, the `last` non-zero position markers, and stereo Mid/Side flags tightly into the output byte stream.
    
    \item \textbf{bytes.cpp} (and WAV handler) manages high-level binary file I/O, writing and reading structural file components, validating the format magic bytes, and extracting raw PCM samples alongside metadata like sample rate, channel count, and bits per sample.
\end{itemize}

\section{Final Adjustments}

Like with the lossless encoder, we expected that block encoding might end up being implemented later on, to improve our compression results, as well as splitting both channels (in the case of stereo) into MID and SIDE channels. However, besides those changes, we have also that identified other possible improvements:

\begin{enumerate}

    \item \textbf{Quantization and centroid reconstruction:} We can replace simple uniform scaling with an advanced deadzone quantizer paired with centroid reconstruction parameters, effectively eliminating faint background noise and recovering precision.

    \item \textbf{Context based Rice encoding:} While before we used a single global parameter for an entire block, often resulting in inefficient bit distribution, we can dynamically calculate and predict an optimal k parameter for every single coefficient.

\end{enumerate}

Comparing as well to our previous iteration, the implementation of a k variable that is context-adaptive, instead of globally set, helped optimize bit allocation across varying coefficient magnitudes, preventing wasted capacity on small high-frequency values and significantly reducing cumulative bit consumption.
